# 05_OPERATIONS
 
How the team actually works. Process, communication, deployment
discipline, infrastructure, content rules. This domain is the *how*;
the *what* lives in product and the *why* lives in foundation.
 
## Files
 
| File | Owns |
|---|---|
| `WORKFLOW.md` | How work moves: the loop, the cadence, the ledger discipline |
| `COMMUNICATION_PROTOCOL.md` | Headers, the bus pattern, confidence tags, disagreement |
| `DEPLOYMENT.md` | Archive-before-change, sandbox-before-ship, rollback vs amendment |
| `INFRASTRUCTURE.md` | The real stack, environments, what lives where |
| `CONTENT.md` | Content rules in the system's voice |
 
## The through-line
 
Every file in this domain enforces one idea: discipline over speed,
and honesty about state. The workflow names what is deferred. The
protocol surfaces disagreement. The deployment rules refuse
irreversible automation. The content rules refuse theater. Operations
is where the doctrine becomes daily behavior.
